# bobina — CLI conventions (draft v0.4)

Status: **implemented in v0.x** (see Implementation notes). Language: **English everywhere** (messages, help, docs, spec).

## Principles

1. **Agnostic core, opinionated defaults.** Anything the user asks for explicitly is executed as asked. Calibrated defaults (from the printer profile) only fill in what was not specified.
2. **Nudges, not blocks.** Warnings go to stderr with a suggestion and the evidence behind it; they never stop a print. `--quiet` silences them, `--strict` turns them into errors (CI/automation).
3. **What you check is what you print.** `check`, `preview` and `print` share one engine. Every printing command accepts `--dry-run`.
4. **Nothing prints without confirmation.** Every command that prints shows the confirmation screen first and waits for `p`. `--yes` (`-y`) skips it, explicitly.
5. **Readable by humans and agents.** Full command names are canonical. Human-readable output by default, `--json` on every command that returns data, stable exit codes.
6. **Discoverable.** `bobina help`, `bobina <command> --help`, `bobina help format`, `bobina help data`, `bobina help pay`, `bobina <thing> list`,
   `bobina help E302` (what a problem code means and what to do; docs/problems/), `bobina help --json` (the CLI for
   programs). JSON outputs have schemas in docs/schemas/.

## Names

- Binary: **`bobina`**. `bob` is an installed alias of the same binary.
- **Canonical form is always the full command name** (`bobina print`, `bobina check`). Docs, help text, examples, error messages and anything generated by the tool use full names only.
- Short aliases exist purely as typing shortcuts for interactive use, are documented in one place (`bobina help aliases`) and are never shown elsewhere.

## Commands

| Command | Does | Alias |
|---|---|---|
| `print [FILE \| - \| "TEXT"]` | render, confirm and print a `.bob.md` document, inline text, or stdin; `--last` reopens the last confirmation | `p` |
| `check FILE` | lint: line breaks, truncated words, unsupported glyphs, paper length, black coverage, nudges | `c` |
| `preview FILE -o OUT.png` | exact bitmap, or `--realistic` (calibrated dot gain) | `pv` |
| `view FILE` | preview in the terminal (block/braille characters) | `v` |
| `edit [FILE] [--template NAME]` | write in your editor → confirmation screen → print | `e` |
| `status` | paper / cover / error / language mode; `--list` explains every state | `s` |
| `mode [esc \| tspl \| cpcl]` | show or switch the printer command language | `m` |
| `send FILE.bin` | send raw bytes untouched (escape hatch) | — |
| `fonts list \| test \| mark` | recommended fonts and the font test registry | — |
| `seq list \| set \| reset` | persistent counters used by `{{ seq.NAME }}` | — |
| `printer scan \| add \| list \| use` | find and store printers (address lives in config, never in code) | — |
| `profile list \| show \| use` | printer profiles | — |
| `template list \| show \| new` | ready-made documents (receipt, label, todo, card, shop tags…) | — |
| `calibrate compare\|tear\|feed` | photo vs preview; tear bar distance (ruler); feeds after images (3 lines) | — |
| `help [COMMAND \| format \| nudges \| aliases]` | help | — |
| `mcp` | a server for AI agents (Model Context Protocol): [Agents](#agents-bobina-mcp) | — |

Everyday use: `bobina print "buy bread"`, `bobina print list.bob.md`, `echo "hi" | bobina print --yes`.

## Confirmation screen

Shown by every printing command (it is the dry run):

```
┌─ preview · mtp-ii-58 · 58 mm ────┐
│ MARKET               05/11/2026  │
│ ☐ milk                           │
│ ☐ bread                          │
└──────────────────────────────────┘
 ~7.2 cm of paper · 4 native blocks, 1 raster
 seq.ticket: will use A-042 (reserved for this print; given back if it is not printed)
 warning[F204] line 3: font "Z003" at 16px is illegible → use ≥ 28px  (evidence: F1-16)

 [p] print   [e] edit again   [s] save as…   [q] quit
```

- Enter alone never prints.
- `print --last` reopens the confirmation of the last document (identical content, same reserved values); `--again` re-renders it (new `now`, new `seq`).
  With `--yes` either one prints at once and says where (`reprinted on loja: ~1.5 cm (identical bytes)`); with
  `-o FILE` it saves the bytes to that file instead and prints nothing (`--again -o` spends no seq numbers).
- No terminal attached (pipes, cron, agents) and no `--yes` → shows the confirmation on stderr, prints nothing, exit code 7.
- `--copies N`: N identical copies. `--repeat N`: N renders, each with new counter values. The screen shows the total ("10 tickets: A-042 to A-051").

## Drafts and editor (`edit`)

```
bobina edit                        # blank draft
bobina edit --template receipt     # draft from a template (fields prefilled, # required / # optional)
bobina edit list.bob.md            # existing file (or create it)
```

- A draft is a full `.bob.md` (front matter, variables, counters, templates), stored in `~/.local/state/bobina/drafts/`; the last one is kept for `print --last`.
- Drafts start with a column ruler as an HTML comment (exact for the native font only; the preview is the truth).
- Editor resolution: `--editor CMD` > `editor` in `config.toml` > `$VISUAL` > `$EDITOR` > `nano` > `vi` (Notepad on Windows).
- GUI editors return immediately unless told to wait; bobina adds the flag for known ones (`code`/`cursor --wait`, `subl -w`).

## Inline text is an implicit document

`bobina print "TEXT"` (and stdin) is treated exactly like a `.bob.md` file with that content: same parser, same check, same nudges.

- `--plain` disables Markdown (prints the text literally, still word-wrapped).
- `\n` in the argument is a newline (typing multi-line text in a shell is awkward): `bobina print "# MARKET\n- [ ] milk"`.
- Backslash before a Markdown character escapes it, as in CommonMark (`\*`, `\#`).
- `check` warns when text looks literal but would be interpreted (e.g. a lone `*`, `#` without a space, a log line starting with `---`).

## Saving instead of printing (`-o`)

`-o FILE` (`--output FILE`) saves instead of printing. An existing FILE is replaced only with `--force`, and a file
the job reads (document, image, data) is never replaced. Without `-o`, `preview` writes `DOCUMENT.preview.png`. In `print` it saves the bytes the printer would get (any
name; `.bin` by convention), to send later with `bobina send`. In `preview` it saves the picture of the strip:
`.png`, `.jpg`, `.pdf`, `.webp`, `.bmp`, `.gif` or `.tif`, chosen by the extension.

**One file per label**: put a placeholder in the name (like ffmpeg's `frame%04d.png`):

| Placeholder | Becomes | Needs data? |
|---|---|---|
| `{n}`, `{n:03}` | label number in the whole job: 1, 2 … / 001, 002 … | no |
| `{i}`, `{i:02}` | number inside its document (restarts for each file) | no |
| `{file}` | document name without the extension (`jar`, `cover`) | no |
| `{part}` | the `--then` part | no |
| `{column}`, `{b.column}` | a value of that row (`{item}` → `rice`) | yes |
| `{column\|slug}` … | the value in another case: `lower`, `upper`, `slug`, `snake`, `kebab`, `camel`, `pascal`, `deaccent`, `titlecase` | yes |

```
bobina preview a.bob.md b.bob.md -o 'out-{n}.png'                     # out-1.png out-2.png
bobina preview cover.bob.md --then jar.bob.md --data kitchen.csv -o 'out/{file}-{i:02}.jpg'
bobina preview jar.bob.md --data kitchen.csv -o 'tag-{item}.png'      # tag-rice.png …
bobina print jar.bob.md --data kitchen.csv -o 'jar-{n}.bin'           # each file is a whole printable job
bobina preview jar.bob.md --data kitchen.csv --pages -o batch.pdf     # one PDF, one page per label
```

Values from data are cleaned for file names (`../../x` cannot leave the folder; `/ \ : * ? " < > |` become `_`).
Two labels that would get the same name are an error (add `{n}` or `{i}`); existing files are replaced only with
`--force`; a missing `{column}` lists the available names. Folders in the name are created.

## One strip (`--compact`, `--then`, several files)

Every label normally ends with the feed to the tear bar, so you can tear each one off. To print several things as
one job — one preview, one confirmation, one paper count — give several files, or split the command into
**parts** with `--then`:

```
bobina print a.bob.md b.bob.md @shelf                        # three documents, one job
bobina print jar.bob.md --data kitchen.csv --compact \
  --then jar.bob.md --data laundry.xlsx --sheet Laundry \
  --then receipt.bob.md --no-compact --compact-all
```

**Rules** (like ffmpeg: options belong to the part they are written in; the specific beats the general):

1. A **part** is everything between two `--then`: one or more files and their options (`--data`, `--where`,
   `--copies-from`, `--set`, `--ask`, `--page` …). The options apply to every file of that part.
2. `--compact` / `--no-compact` set a part; `--compact-all` is the default for every part. Both flags in one part
   is an error.
3. **Joins**: inside a compact part, labels are glued at a ✂ cut. Between two parts there is a ✂ cut only if
   **both** are compact; otherwise the paper feeds to the tear bar. The end of the job always feeds.
4. Job options (`--compact-all`, `--yes`, `--dry-run`, `--printer`, `--profile`, `--marks`, `-o`) may be written
   in any part. Counters (`{{ seq.x }}`) continue across parts and files; copies of a row repeat its number.

The terminal preview always draws where one label ends (decided 08/11: symbols, no words): `┄┄ ⟶ ┄┄` where the
paper goes to the tear bar, `✂ ┄┄┄` at a cut.

**On paper, no mark by default** (a cut is just space). To see on the strip where one order ends and the next
begins, `--marks cut` prints a fine dashed line (1 dot, 4 on / 4 off) at every cut, `--marks tear` prints it so
that the final feed leaves it on the tear bar (it uses the `tear_mm` measured by `bobina calibrate tear`; 5 mm
without one), `--marks both` does both; `marks = "both"` in `config.toml` makes it the default. The marks change
no length, and the confirmation screen says which ones go on paper.

| Command | Strip (⟶ tear feed, ✂ cut line) |
|---|---|
| `a b --then c d --compact` | A ⟶ B ⟶ C ✂ D ⟶ |
| `a b --then c --then d --compact` | A ⟶ B ⟶ C ⟶ D ⟶ (D's neighbour is not compact) |
| `a b --then c --no-compact --then d --compact-all` | A ✂ B ⟶ C ⟶ D ⟶ |
| `jar --data kitchen.csv --compact --then jar --data laundry.xlsx` | jar 1 ✂ jar 2 ✂ jar 3 ⟶ jar 4 ⟶ jar 5 ⟶ |

**Which options belong where** (tested in `tests/test_strip_rules.py`):

| Kind | Options | Rule |
|---|---|---|
| Part | `--set`, `--data`, `--sheet`, `--rows`, `--where`, `--copies-from`, `--repeat`, `--copies`, `--ask`, `--page`, `--plain`, `--allow-net`, `--allow`, `--compact`/`--no-compact` | apply to the files of the part they are written in, never to the next part |
| Job flag | `--compact-all`, `--yes`, `--dry-run`, `--strict`, `-q`, `--json`, `--no-color` | may be written in any part, apply to the whole job |
| Job default | `--set-all KEY=VALUE`, `--allow-all CODES` | every part gets them; a part's own `--set`/`--allow` wins |
| Job value | `--printer`, `--profile`, `-o`, `--editor` | one value per job; two different values are an error |
| Not with documents | `--last`, `--again` | reprint the last job; an error with targets or `--then` |

**Errors and warnings in a long job.** Every part is built and checked before the printer is touched, and every
problem is reported at once, in one format (the same in every command):

```
3 errors, 1 warning — nothing printed
✗ error   part 2 (nope.bob.md): file not found: nope.bob.md
✗ error   part 4 (jar.bob.md): --where: no column 'color' (columns: item, n)
✗ error   [M310] part 5 (bad.bob.md): templates cannot read files (include/import are disabled)
! warning [I101] part 3 (photo.bob.md), line 3: image 'missing.png': No such file or directory
            → paths are relative to the document
```

One error anywhere and nothing prints; the exit code is the most serious one (security 8 > document 2 > usage 1).
Warnings never stop the job by themselves: on the confirmation screen you decide (`p` prints without the missing
image, `q` gives up); with `--yes` they are shown and the job prints anyway; with `--strict` any warning stops
everything (exit 3), also with `--yes` (`--yes` only skips the confirmation screen). So either the whole strip prints or nothing does. Literal text `--then` cannot be printed:
it always separates parts. `--dry-run` shows the whole strip (up to 12 labels on
the terminal; `bobina preview -o strip.png` has all of them) and every warning; the confirmation screen shows the
same before `p`. Only one part can read stdin (`-`).

Several targets are files, `@names`, images or URLs; plain words are refused (`bobina print hello world` →
use quotes: `bobina print "hello world"`). `--last` reprints a multi-part job as it was; `--again` re-renders
only single documents. The tested cases are in `tests/test_strip_rules.py`.

## Saved labels (`library`, `@NAME`)

Labels printed often are saved once and printed by name, without opening an editor:

```
bobina library add shelf shelf-label.bob.md --note "pantry shelf"
bobina library add bread "# BREAD\nbest before {{ today | add(days=3) | date }}"
bobina library list                         # @shelf  pantry shelf  fields: item (--set or --ask)
bobina print @shelf --set item=Rice         # or --ask; preview and confirmation as usual
bobina library show shelf · bobina library rm shelf
```

An entry is a snapshot in `~/.config/bobina/library/` plus the folder it came from, so relative images keep
working; `@NAME` works anywhere a FILE does (`print`, `check`, `preview`). Names are letters, digits, `.`, `_`
and `-`: never paths. `--force` replaces an entry.

## Filling a template on the terminal (`--ask`)

```
$ bobina print --ask receipt.bob.md
Fill in the fields (Enter = default / leave empty):
shop (required) e.g. Padaria do Zé: Padaria do Zé
items (required) - list of [item, quantity, unit price]
  one row per line: item; qty; price  (empty line to finish)
  1> pão; 2; 1.50
  2> café; 1; 4
  3>
currency - ISO 4217 code [BRL]:
date [automatic]:
```

Only the fields still missing are asked; answers are literal data, like `--set`. Then the usual preview and
confirmation follow.

## Images, SVG and PDF as the target

`bobina print photo.jpg`, `bobina print logo.svg`, `bobina print label.pdf --page 2` (or `--page 1-3`; default: all
pages, one image per page) build a one-image document and go through the same preview and confirmation. Vector
files are rendered at the paper width and thresholded (crisp text and lines). Typical use: export a label from
another app (Dlabel, a browser, Office) as PDF and print it with bobina's calibration.

A file is recognized by its content, not only its name. Anything else (Word, Excel, PostScript/EPS, binary
files, a broken image) is refused with the list of supported formats and a hint to export as PDF: printing it
would waste paper on garbage, so this is an error, not a nudge. Inside a document the same problems are
nudges (`I101`) and the rest prints; a document with nothing left to print adds `L105`.

`bobina print https://… --allow-net` does the same for an https image. Network images are off unless the command
line says `--allow-net`, never from a document by itself; private and local addresses are refused (see
`docs/SECURITY.md`).

## Shape

```
bobina [global options] <command> [arguments] [command options]
```

Global options:

| Option | Effect |
|---|---|
| `--profile NAME` | printer profile (default: configured; base `mtp-ii-58`) |
| `--printer ADDRESS` | target device (default: from config/profile) |
| `--quiet` | no nudges |
| `--strict` | nudges become errors (exit 3) |
| `--json` | structured output |
| `--dry-run` | never touch the printer |
| `--yes`, `-y` | print without the confirmation screen |
| `--verbose` / `--debug` | more detail / dump bytes sent |
| `--no-color` | no color (also honors `NO_COLOR`) |
| `--help`, `--version` | |

Short flags are allowed only for the most common options (`-o` output, `-q`, `-n` dry-run, `-y`, `-h`) and, like command aliases, are never used in docs or generated output.

Configuration precedence: **flag > document front matter > `~/.config/bobina/config.toml` > profile > built-in default**.

## Help layout

`bobina COMMAND --help` (argparse) has the same parts for every command:

```
usage: bobina print [-h] [--profile PROFILE] … [target ...]

bobina print — print a document, inline text or stdin

positional arguments:
  target        a .bob.md file, "TEXT" (\n = new line), or - for stdin; several = one strip

options:        the options of this command (--data, --then, -o …)

global options: --profile, --printer, -q, --strict, --json, --allow, --problems …
                (-n/--dry-run, -y/--yes and --editor listed only on commands that print)

EXAMPLES
  bobina print "buy bread"
```

A wrong option shows the usage of that command, not of bobina, and one hint:

| Typed | Hint |
|---|---|
| `print --copies-form 2` | did you mean --copies-from? |
| `print --dryrun`, `--dry_run`, `--DRY-RUN`, `-dry-run` | did you mean --dry-run? |
| `print --planilha x.xlsx` (a synonym, also Portuguese) | did you mean --data? |
| `print --jon` (equally close to three) | did you mean --join, --json or --on? |
| `print --pages` | did you mean --page? (… --pages is an option of bobina preview) |
| `check --output x` | --output belongs to bobina print or bobina preview, not bobina check |
| `preview --yes` (also `-n`, `--editor`) | not an error: runs, with `note: --yes does nothing in bobina preview: it never prints` |

A new command or option goes through the checklist in CONTRIBUTING.md; a test fails until it does.

## Lists

Pattern: `bobina <thing> list` — table for humans, `--json` for machines.
`bobina status --list`, `bobina fonts list`, `bobina profile list`, `bobina template list`, `bobina help nudges`.

## Nudges

Flow of warnings, refusals and prints: [`docs/diagrams/nudges-flow.md`](diagrams/nudges-flow.md).

One format on stderr, with a stable code so they can be filtered or allowed:

```
warning[B101] line 12: 1px stroke prints broken on profile mtp-ii-58 → use 2px  (evidence: R4-01)
warning[F204] line 3: font "Z003" at 16px is illegible → use ≥ 28px or Atkinson 16px  (evidence: F1-16)
```

- Code = category + number: `B` drawing, `F` font, `Q` barcodes/QR, `L` layout, `I` image, `P` printer, `M` markup.
- Always: where, what, suggestion, evidence (the test id that justifies it).
- `--quiet` silences all; `--allow B101,F204` (or front matter `allow: [B101]`) silences specific ones.

## History (`bobina history`)

Every `bobina print` is recorded, whatever happens: printed, cancelled, failed, saved (`-o`), dry run or stopped by
`--strict`. One JSON line per job in `~/.local/state/bobina/history.jsonl` (schema `bobina.history/1`): id, time,
duration, outcome and exit code, printer and profile, labels, length, ✂ cuts and tear feeds, the parts (file names),
counters used, every problem (same fields as `--problems json`) and the sha256 of the bytes sent.

```
bobina history                              # newest first, one line per job (like git log --oneline)
bobina history --long --limit 5             # every detail
bobina history --outcome failed --since 2026-11-01
bobina history show last                    # or an id, or the start of one
bobina history stats                        # jobs by outcome, labels, paper per week, frequent problems
bobina history --json · bobina history clear --yes
```

Private by default: the text of labels is not kept; on the stored command line, inline text becomes `text`,
`--set`/`--set-all`/`--where` keep only the key (`KEY=***`, they can be a Pix key or a phone number) and option
values are kept only for file and number options. Problem messages are stored with every value given to the job,
long digit runs and e-mails replaced by `***`. Abbreviated options are refused, so none slips past this. `history = false` in `config.toml` turns it off;
`history_max` (default 5000) bounds it.

## Problems: one format, four renderings

Every error, warning and note has a code from the catalog (`bobina help nudges`; errors are `E1xx`–`E5xx`) and
the same fields. `--problems` (any command; or `BOBINA_PROBLEMS`) chooses how they are written to stderr:

| Format | For | Example |
|---|---|---|
| `pretty` (default) | people | `! warning [I101] part 3 (f.bob.md), line 3: image 'missing.png' …` + `→ hint` |
| `plain` | grep, scripts | `warning I101 part 3 (f.bob.md) line 3: image 'missing.png' … -- hint` |
| `json` | one document | `{"outcome": "nothing printed", "problems": [ … ]}` |
| `jsonl` | logs | one object per problem per line |

Fields (schema `bobina.problem/1`): `code`, `severity` (`error`/`warning`/`note`), `message`, `suggestion`,
`line` (in the document, or null), `evidence` (the printed test behind a limit), `outcome` (`nothing printed`,
`printing anyway (--yes)`, `nothing printed (dry run)`, `nothing saved` for preview, empty for check and view …)
and, in multi-part jobs, `source`, `part` (number) and `file`. Exit codes are below; the most serious problem decides it.

The problems always go to **stderr**, so stdout stays free for the data of the command: `--problems json > f`
saves the human summary, not the JSON. To keep the problems of a document in a file, use `check --json`, which
writes them to stdout in the same shape, next to the paper figures:
`bobina check doc.bob.md --json > problems.json` → `{"stats": {…}, "problems": [ … ]}`. `print --json` and
`preview --json` write the same, next to what happened (`outcome`, `exit`, `saved_to`; `files` for preview): one
object on stdout, schemas in docs/schemas. `view`, `edit`, `send`, `mode` and `mcp` write no data: there `--json`
does nothing and a note says so.

## Two commands at the same time

Two terminals, a script and the tower over ssh may run bobina at once. Its own files stay whole:

- **seq numbers** never repeat (see FORMAT.md, counters): each print reserves its numbers under a lock.
- **One job per printer.** A second print waits for the first ("waiting for the printer: another bobina job is
  using it…") instead of fighting for the Bluetooth link. After `busy_timeout` seconds (printer entry in
  `config.toml`, default 300) it stops with `E405` and nothing is sent. `bobina status` during a print answers
  `E405` at once.
- **Paper, history, saved labels, config, --last**: every change is made under a lock and written whole (temporary
  file + rename), so a reader never sees half a file and two changes never lose one another.
- **A damaged file is an error, not a fresh start** (`E209`, with the file name): an empty `counters.json` would
  restart the numbering. bobina never overwrites it; fix it or move it away. The paper odometer only advises: a
  damaged `paper.json` is shown on the confirmation screen and the print goes on.

## Long jobs and limits

- **Previews of long strips are split.** Above ~2.5 m (20000 dots) one image does not open in most viewers:
  `preview -o tira.png` writes `tira-1.png`, `tira-2.png` … and says so. Each page is drawn and saved on its own
  (one page in memory); previews are 1-bit PNGs.
- **`--last` keeps the exact bytes and the preview of the labels the terminal showed** (up to 12), not a drawing of
  the whole job.
- **Nothing waits forever.** A download has 20 s in all (DNS included), a device file (`transport = "file"`) and
  a `command` printer have `timeout` (printer entry, default 120 s), `bluetoothctl` calls are bounded. stdin takes
  up to 10 MB (a document), `bobina send -` up to 64 MB.
- **Servers, bots, cron: `BOBINA_NONINTERACTIVE=1`.** bobina never asks on the terminal: `--ask` and the
  confirmation stop at once with `E107` (pass `--yes` and `--set`). Also give the target explicitly and start
  bobina with stdin closed (`stdin=DEVNULL`): with no target, bobina reads a document from stdin.
- **One process per job.** bobina keeps some settings per process (problem format, Pillow's image size limit,
  caches), so call it as a command, not as a library from several threads. A server runs one `bobina`
  subprocess per job (`start_new_session=True`), behind a queue per printer; that also bounds the memory of each
  job.

## Agents (`bobina mcp`)

`bobina mcp` is a Model Context Protocol server on stdin/stdout for agents (Claude Code, Claude Desktop, Cursor).
It needs an extra: `uv tool install 'bobina[mcp]'`.

```bash
claude mcp add bobina -- bobina mcp                  # Claude Code
claude mcp add bobina -- bobina mcp --printer test   # defaults of check, preview, print (and status, paper)
```

`--printer`, `--profile`, `--allow` and `--strict` given to `bobina mcp` are the defaults of the document tools;
`--printer` is also the default of `status` and `paper`.

Claude Desktop, Cursor: `{"mcpServers": {"bobina": {"command": "bobina", "args": ["mcp"]}}}` in their MCP config.

| Tool | Runs |
|---|---|
| `check` | `check --json`: stats and problems, nothing printed |
| `preview` | `preview --json`, every file listed and attached as images up to 10 (temporary files unless `output`) |
| `print` | `print --dry-run --json`; with `confirm: true` (after the user agreed), `print --yes --json` |
| `template_list`, `template_show` | `template list --json`; `template show NAME --json` and the document to fill |
| `help` | `help TOPIC [NAME] --json`: a topic, a problem code (`Q111`), a pay scheme (`pay pix`) |
| `status`, `paper` | `status --json`, `paper --json` |

The document is `text` (given on stdin) or `path` (absolute, or `@NAME`); the other arguments are the options of
the command: `set`, `data`, `profile`, `printer` (check and preview take it too: look with the printer print
uses), `allow`, `allow_net`, `strict`, `copies`. Each result starts with the command line it ran and its exit
code, then the CLI's JSON (docs/schemas) and stderr, where problems are written as `--problems json`. It is an
error unless the exit is 0 or 9. Each call is one bobina process with `BOBINA_NONINTERACTIVE=1`, no stdin and a
session of its own: the safety is the CLI's (sandboxed templates, network images only with `allow_net`, the
limits above). A call that does not finish (300 s; a print 1800 s) or that the client cancels is stopped with
everything it started (Ctrl-C, then a kill); its result has no exit code and, for a print, says that part of the
job may already be on paper: check the paper and `bobina history` before printing again.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | ok |
| 1 | usage error |
| 2 | document error (parse) |
| 3 | nudges with `--strict` |
| 4 | printer unreachable / Bluetooth |
| 5 | printer error state (no paper, cover open) |
| 6 | printer language mismatch (e.g. printer in TSPL, document needs ESC/POS) |
| 7 | confirmation required (no terminal and no `--yes`) or declined |
| 8 | security error (template sandbox violation, see FORMAT.md §7) |
| 9 | the job went out (printed, saved, shown) without a part it exists for: a payment code that was not built (`Q111`). The rest printed; `--allow Q111` makes it 0 |

## Install and files

- `uv tool install bobina` (or `pipx`) → `bobina` and `bob`.
- Implementation: Python + Pillow (reuses the test tooling), `jinja2` (sandboxed), `babel` (CLDR). Modules: parser → layout → render → transport.
- Config: `~/.config/bobina/config.toml` (default profile, printers, editor, preferences).
- Profiles: built-in + `~/.config/bobina/profiles/*.toml` (width in dots, `dpi`, native fonts, capability matrix, top margin, `feed_after`, calibration curve).
- State (counters, drafts, last print): `~/.local/state/bobina/`.

## Decided

- English everywhere.
- Inline text and stdin are implicit `.bob.md` documents; `--plain` opts out.
- Full names are canonical; aliases are typing shortcuts only.
- Confirmation before every print; `--yes` to skip; exit 7 without a terminal.
- `edit` without a file = draft in the state folder; editor resolution as above.
- `print --last` reopens the confirmation; `--copies` identical vs `--repeat` new values.
- Printer address in config (`printer scan/add`), never in code.
- Profile `feed_after` so the last line clears the tear bar.

## Implementation notes (v0.x, 2026-11-05)

- Commands implemented: `print`, `check`, `preview` (`--realistic`), `view`, `edit` (`--template`), `status` (`--list`), `mode`, `send`, `printer scan|add|list|use|remove`, `profile list|show`, `fonts list`, `template list|show|new`, `seq list|set|reset`, `calibrate compare PHOTO FILE`, `help format|data|pay|nudges|aliases|COMMAND`.
- `print` also takes `--data FILE` (one label per row, values literal; CSV, TSV/TXT with the delimiter detected,
  Excel `.xlsx` with `--sheet`, JSON list of objects), `--rows N-M` (data rows, 1 = first after the header),
  `--where COL=VAL|COL!=VAL|COL~=TEXT` (repeatable, case-insensitive), `--copies-from COL` (identical copies per
  row, 0 skips it; counters advance once per row), max 1000 labels per job, `--repeat N`, `--copies N`, `--set KEY=VALUE`, `-o FILE` (bytes to a file: not printing, no confirmation).
- Printers: `transport = bluetooth` (RFCOMM; status checked on the same link before printing → exit 5 if cover open/paper out), `command` (bytes piped to a command, e.g. `ssh tower bobina send --yes -`), `file` (append to a file or device).
- Confirmation is read from `/dev/tty`, so `cat x | bobina print` still asks; no terminal and no `--yes` → exit 7.
- Exit code 8: security error (template sandbox, variable in a raw block or image path).
- `bobina edit` drafts live in `~/.local/state/bobina/drafts/`; the last print in `~/.local/state/bobina/last/` (`--last` resends identical bytes, `--again` re-renders).
- **A new printer, step by step:** `bobina calibrate tear` prints a ruler with no feed after it: tear at the serrated
  edge and read the mm (`bobina calibrate tear 5`); jobs then end with that distance + 6 mm (`tear_margin_mm`).
  `bobina calibrate feed` prints three lines, A–B 10 mm drawn as an image and B–C a 10 mm paper feed (ESC J) sent
  right after B: if B and C touch, the printer ignores a feed right after an image (the MTP-II does) and
  `bobina calibrate feed touching` keeps the safe mode; `apart` turns it off. **Safe by default** (08/11): a printer
  nobody measured sends every feed that follows an image as white raster rows (48 bytes per dot row instead of 3
  bytes per feed) and waits until the printer is idle before the end of an image job; both are per-printer keys in
  `config.toml` (`blank_rows_after_raster`, `idle_before_tail`).
- **What a profile turns on** (`bobina profile show NAME` lists it). Three features follow the ESC/POS spec and are
  tested on the bytes only; a job that uses one gets the note `P301` (docs/TESTED.md):
  - Code pages: `encoding = "codepage"` and a `[codepages]` table (codec = `ESC t` number, in order of preference):
    accented text stays native, switching page where a character needs it. **⚠ not tested on paper.** With
    `encoding = "utf-8"` (the MTP-II) text goes as UTF-8; with `"ascii"` only ASCII is native, the rest raster.
  - Automatic cutter: `cutter = "full"` or `"partial"` cuts (`GS V`, where the paper is) after the final feed of each
    label; `--compact` labels stay glued, to be cut by hand.
    **⚠ not tested on paper.** `bobina calibrate tear` then measures the distance to the blade.
  - Native barcodes on imported profiles (`barcode.native` from the printer database). **⚠ not tested on paper.**
- `calibrate compare` finds the paper in the photo, scales it to the printable width and reports length error, row-profile correlation and a 0–100 score, plus a side-by-side PNG (exact | realistic | photo).
- `bobina paper` (2026-11-05): a paper odometer per printer. `paper new 15m` (or `--diameter 40mm --core 12mm --thickness 0.06`) when a roll is loaded; every confirmed print adds its exact length; the confirmation shows the metres left, `P101` when the roll is almost over (< 1 m or 10%), `P102` when the print is longer than what is left. `paper used 3m` sets the total used, `paper used +30cm` adds to it (prints from other apps, raw `send` jobs and the self-test are not counted). On "paper out" the error suggests `paper new`.
